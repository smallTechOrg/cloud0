## Intake

- **Symptom:** every gcloud credential on the machine was expired; `gcloud` cannot prompt for re-auth in a non-interactive session, so the environment research the user asked for was blocked at first. **Did:** asked the user to run `gcloud auth login` in their own terminal, continued intake meanwhile, re-checked token validity cheaply before resuming research. **Lesson:** the intake should include a "cloud CLI auth is live" preflight the moment an idea mentions a cloud provider, and the skill should say that re-auth is a user-only step.
- **Symptom:** `gcloud alpha monitoring policies list` and `gcloud beta error-reporting ...` tried to install SDK components and hung on a y/N prompt. **Did:** used the GA `gcloud monitoring policies list` and the REST APIs via `curl` + access token instead. **Lesson:** never call `gcloud alpha|beta` in non-interactive runs; prefer GA commands or REST.
- **Symptom:** `bq show --format=json` for a table printed a non-JSON banner first in one invocation, breaking a JSON parse. **Did:** re-ran with `--schema --format=prettyjson`. **Lesson:** pipe `bq` output through a tolerant parser or use `--schema`.
- **Symptom:** a Monitoring aggregation grouped by `metric.labels.instance_name` returned series whose `metric` had no `labels` key for Ops Agent metrics. **Did:** noted that Ops Agent series carry the instance in `resource.labels`; parse both. **Lesson:** group-by fields differ between `compute.googleapis.com` and `agent.googleapis.com` metrics.
- **Observation:** the user answered intake with mid-turn free-text messages (not via the question tool) twice; the skill handled it but the question tool's single-select "frontend" answer was later overridden by text. **Lesson:** always re-read mid-turn messages before invoking the builder; treat the latest statement as binding.
- **Observation:** the target repo is public; the harness has no "public repo → identifiers via env only" rule. Added as a brief constraint. **Lesson:** intake technical round should ask repo visibility.

## Design / scaffold (first builder invocation)

- **Symptom:** the scaffold code-generator could not run a single Bash command: the macOS Data volume had ~235 MiB free (204 GiB of 228 GiB used) and the tool's output-capture file hit `ENOSPC`. **Did:** stopped the build before any scaffold file was written, committed the spec so the design work is durable, and returned a BLOCKED handoff with the largest reclaimable directories listed (sizes only; nothing deleted — freeing space is the user's call). **Lesson:** intake/preflight should check free disk (`df -h`) and require a few GB headroom before a build that pulls Go module graphs, node_modules and a Playwright browser.
- **Symptom:** `GO111MODULE=off` is persisted in `~/Library/Application Support/go/env`, so bare `go build`/`go test` inside a module fails on this machine. **Did (planned for the scaffold):** the Makefile exports `GO111MODULE=on` and `GOTOOLCHAIN=local`; README notes the prefix for direct `go test` invocations. **Lesson:** preflight should print `go env GO111MODULE GOTOOLCHAIN` when the stack is Go.
- **Symptom:** latest releases of `modernc.org/sqlite`, `pressly/goose/v3` and `cloud.google.com/go/bigquery` declare `go >= 1.26`, which the binding Go 1.23 toolchain refuses without an auto-download. **Did (planned):** pin the newest Go-1.23-compatible versions with `GOTOOLCHAIN=local`. **Lesson:** when the user binds an older toolchain, the spec should say "pin deps to the toolchain" and the generator should probe before `go get`.
- **Symptom:** `go mod tidy` rewrites `go 1.23` to `go 1.23.0` (every pinned dependency declares `go 1.23.0`, and Go orders `1.23 < 1.23.0`) and, on the first bump, adds a `toolchain go1.23.3` line. **Did:** `go mod edit -go=1.23.0 -toolchain=none` after tidy; with the go line already at `1.23.0` later tidies add nothing. **Lesson:** a spec that says "`go 1.23`, no toolchain directive" should expect `go 1.23.0` — same minimum, and the toolchain line must be removed once by hand.
- **Symptom:** `modernc.org/sqlite` had to go back 22 releases (v1.61.0 → v1.39.0) to find a `go.mod` accepting Go 1.23; `goose` v3.26.0 and `bigquery` v1.70.0 were the newest 1.23-compatible releases. Probing was done with `go mod download -json module@version` and reading the `GoMod` file's `go` line. **Lesson:** record the probe loop as a reusable snippet in the stack preflight; binding an older toolchain costs real currency on fast-moving deps.
- **Symptom:** the asdf `pnpm` shim is bound to Node 25.2.1 by `/Users/sai/Workspace/Code/.tool-versions` (a parent directory of the repo), not the Node 22.23.1 at `/Users/sai/.local/bin/node` the brief named; `pnpm install` warned "Unsupported engine" against `engines.node >=22 <23`, and vitest 5 does not list Node 25 as supported. pnpm 11 ignores `use-node-version` in both `.npmrc` and `pnpm-workspace.yaml`. **Did:** the Makefile runs pnpm's entry file directly with the pinned node (`$(NODE) $(shell asdf which pnpm)`), which makes every script and `pnpm exec` run on Node 22; README documents the same invocation. **Lesson:** preflight should print the Node version *inside* `pnpm exec node -p process.version`, not just `node --version`, and check for `.tool-versions` files above the repo.
- **Symptom:** vitest 5 warns when `vitest.config.ts` uses ESM syntax in a CommonJS package; Next 16 rewrites `tsconfig.json` on first build (`jsx: react-jsx`, extra `include`) and warns about `rewrites` under `output: 'export'`. **Did:** `"type": "module"` in `web/package.json` (Playwright config uses `import.meta.dirname`), committed the tsconfig Next produced, and defined the dev-only `/api` rewrite only when `NODE_ENV=development`. **Lesson:** run the frontend build once before writing tsconfig by hand; let the framework settle the file.

## Phase 1

- **Symptom (S1, billing source):** the spec's error table says `table_not_found` is detected by a `404 notFound`, but against the real API a query on a **non-existent dataset** returned `403 accessDenied` with the hedge "…or perhaps it does not exist" — BigQuery will not disclose existence to a caller without dataset-level access; only a missing *table inside a readable dataset* yields a 404. **Did:** kept the spec's code mapping (403 → `permission_denied`), appended a sentence to that hint telling the user to also check `CLOUD0_BILLING_EXPORT_TABLE` whenever the message carries the hedge, and split the integration tests into "wrong table in the configured dataset" (real 404 → `table_not_found`) and "wrong dataset" (hedged 403). **Lesson:** a spec's provider-error → code table should be verified against the real API's permission model at design time; cloud APIs routinely report "not found" as "forbidden" for least-privilege callers, so hints must cover both readings.
- **Symptom (S1):** the slice instructions asked for `go vet ./...` clean, but with slices fanned out in parallel the module-wide vet was red on another slice's Red-phase test file (`internal/store/snapshots_test.go` referencing a type S2 had not written yet). **Did:** vetted `./internal/billing/` plus every package except the in-progress one; reported the module-wide result honestly instead of touching S2's files. **Lesson:** when slices run concurrently, a slice gate should vet/build only the packages it owns (plus their dependencies); the module-wide `go vet ./...` belongs to the phase gate after all slices land.
- **Symptom (S1):** re-running the identical smoke query within minutes was a BigQuery **cache hit** (`cache_hit=true`, `bytes_processed=0`, `bytes_billed=0`), so "bytes_billed > 0" and "bytes_billed < 200 MB" are not stable assertions on their own. **Did:** assertions accept `cache_hit` as the alternative (as `spec/capabilities/provenance.md` already allows) and the dry run — which is never cached — carries the scan-size check. **Lesson:** gate language about bytes billed needs the cache caveat everywhere it appears (roadmap S1 gate, refresh-snapshot.md), and dry-run bytes are the right scan-hygiene signal.
- **(S2) Symptom:** the slice brief handed to the code-generator paraphrased the Cost-table column keys (`cloudsql`, `ai_cost_groq`, `claude_usage`) while `spec/api.md` and `spec/capabilities/cost-table.md` say `cloud_sql`, `stub:groq`, `stub:claude`. **Did:** followed the spec (api.md is law) and reported the discrepancy in the handback. **Lesson:** orchestrator slice briefs should quote identifier tables from the spec verbatim (or just point at the spec section) instead of paraphrasing them — a paraphrase is a second source of truth that parallel slices (S3, S4) could diverge on.
- **(S2) Symptom:** `spec/data.md → Portability` lists the SQLite-isms to avoid (`strftime`, `json_*`, `RETURNING`) but is silent on upserts, which the annotations capability needs atomically. **Did:** used `INSERT … ON CONFLICT (…) DO UPDATE SET … = excluded.…` (SQLite ≥ 3.24 and Postgres share it) and a single `UPDATE … CASE "key"` for the two-row settings write, so each stays one statement on either engine. **Lesson:** when a spec declares a "portable SQL subset", it should enumerate the allowed upsert form explicitly; otherwise every slice has to re-derive it.
- **(S4) Symptom:** the slice brief named the CSV download `cloud0-cost-<scope>-<date>.csv` while `spec/ui.md` and `spec/capabilities/cost-table.md` both say `cloud0-cost-<scope>-<from>-<to>.csv`. **Did:** followed the spec and asserted the `<from>-<to>` shape in the e2e. **Lesson:** same as the S2 entry — slice briefs should point at the spec section instead of paraphrasing names the e2e will assert on.
- **(S4) Symptom:** while S3 is still in flight every Phase 1 route answers `404 not_found` with `hint: null`, so the "show the banner with the hint" requirement for the pre-S3 UI had nothing to render beyond the code and message. **Did:** the banner renders the hint only when present (the contract allows `null`), and the pre-S3 smoke asserted code + message instead. **Lesson:** a scaffold's unmatched-`/api/v1/*` handler could carry a fixed hint ("no such route in this build — check spec/api.md and the slice that owns it") so unbuilt-route banners are self-explanatory during fan-out.
- **(S4) Symptom:** a one-off headless check (plain Node script, not a Playwright spec) could not `import('…/web/node_modules/playwright/index.mjs')` — with pnpm only direct dependencies get a top-level `node_modules` entry, and the project depends on `@playwright/test`, not `playwright`. **Did:** `createRequire(web/package.json)` + `require('@playwright/test')`, which re-exports `chromium`. **Lesson:** ad-hoc browser scripts in a pnpm project should resolve via `createRequire` from the package's manifest, never by hand-built `node_modules` paths.
- **(S4) Symptom:** `Math.round` rounds half toward +∞, so a shared 2-dp formatter rendered `-12.346` differently from `12.346` and a Vitest value chosen as `-12.345` sat on a float half-case. **Did:** sign-symmetric rounding (`sign × round(|x|·100) / 100`) in both the CSV and display formatters, and test values off the half boundary. **Lesson:** a money-formatting checklist item — "negatives mirror positives; never `-0.00`" — belongs in the frontend conventions so each project does not rediscover it.

## Final integration (Phases 3-4 fan-out)

- **Symptom:** parallel workers writing sibling files in one Go package produced duplicate declarations (same helper or type defined in two new files), so the package only compiled after a human reconciled them. **Lesson:** give each worker a file-name prefix and a list of exported/unexported names it owns; a shared helper goes in exactly one named file that only one worker may edit.
- **Symptom:** a worker used `t.Context()`, which needs Go 1.24, in a module pinned to Go 1.23 (`GOTOOLCHAIN=local`). **Lesson:** put the toolchain version and the banned newer stdlib APIs in every worker brief; use `context.WithCancel` plus `t.Cleanup`.
- **Symptom:** `sed -i -E ...` on macOS (BSD sed) treats the next argument as the backup suffix, which broke the edit or left stray backup files. **Lesson:** never use `sed -i` in a brief; edit with a script (python) or the editor tool, and check `git status` for stray files afterwards.
- **Symptom:** live tests leaked cloud resources when `defer Close()` on the client ran before the deletes registered with `t.Cleanup`. **Lesson:** register `Close` first with `t.Cleanup` (runs last) and register each delete the moment the create returns, before checking the error; make cleanup failures loud.
- **Symptom:** a frozen contract and a slice brief disagreed (for example the propose endpoint answered 200 `enabled:false` in the old roadmap and capability text but 503 `proposer_not_configured` in the frozen `spec/api.md`). **Lesson:** the brief must point at the spec instead of restating it, and the spec owner updates every capability and roadmap line in the same edit that freezes the contract.
- **Symptom:** worker reports described intermediate states of sibling packages (red builds, missing symbols) that no longer held when the root integrated. **Lesson:** treat a worker's "passes" as true only for its own package at that moment; the root re-runs the full gate after the last worker lands.
- **Symptom:** the first full Playwright run exposed what unit tests with fixtures could not: the Monitoring incidents filter used `open_time<"..."` but the real API supports only equality, `>=` and `<=` (HTTP 400), so the Incidents history was empty with an error banner; stale e2e assertions still expected tabs to be stubs; and the footer still said "9 tabs are labelled stubs". The live Go test for log-match alert templates also showed a missing Cloud Logging permission (`logging.notificationRules.create`) that the generic hint attributed to the wrong role. **Lesson:** every filter or query-language string needs one real-API test, and when a phase turns stubs into real tabs, grep e2e specs and UI copy for the stub text in the same change.
